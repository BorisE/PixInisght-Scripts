## Режимы и Use cases

### 1. PATHMODE.PUT_IN_ROOT_SUBFOLDER
Подразумевает, что все исходые файлы уже находятся внутри папки объекта
После обработки все файлы, которые найдутся в подпапках внутри структуры каталогов, будут размещены в единой стандартной структуре откалиброванных файлов

Вход: M63

M63 / 2019-04-28 	/ *
	/ 2019-04-28 	/ bad			/ *

Выход:
M63	/ calibrated 	/ calibrated
					/ cosmetized
					

На выходе: авто структура калиброванных внутри M63
Проверка недостающих звеньев цепи: работает (оптимальный режим для нее)

### 2. PATHMODE.PUT_IN_OBJECT_SUBFOLDER
Удобно использовать после съемки, пока все файлы за ночь в том числе по разным объектам находятся в одной папке.
Скрипт сам сгруппирует на выходе по объектам 

Вход: 
2019-04-28	/ *


Выход:
2019-04-28	/ M63	/ calibrated
					/ cosmetized
			/ M92	/ calibrated
					/ cosmetized

Каталоги на выходе созаются автоматически
Проверка недостающих звеньев цепи: работает, но если будут файлы с одинаковыми именами в подпапках - будет считать их одним файлом

### 3. PATHMODE.ABSOLUTE
Вывод в заданную папку
Вход: 
input folder	/ *

Выход:
output folder	/ calibrated
				/ cosmetized

Проверка недостающих звеньев цепи: работает
				

### 4. PATHMODE.RELATIVE
Режим создания калиброванных файлов в каждой папке

Вход:
2019-04-28	/ *
2019-04-29	/ *
			/ bad	/ *

Выход:
2019-04-28	/ calibrated
			/ cosmetized
2019-04-29	/ calibrated
			/ cosmetized
			/ bad	/ calibrated
					/ cosmetized

Проверка недостающих звеньев цепи: не тестировалось; должна работать, но файлы с одинаковыми именами в разных папках будет считать одним файлом


### 5. PATHMODE.RELATIVE_WITH_OBJECT_FOLDER

Тоже, что и (4), только будут создаваться каталоги для каждого объектаы

Проверка недостающих звеньев цепи: не тестировалось; должна работать, но файлы с одинаковыми именами в разных папках будет считать одним файлом

PUT_FINALS: не применимо, будет работать как и в варианте 


### 6. PATHMODE.AUTO
Не реализована, но должна определять какой режим включать: PutInRootSubfolder или PutInObjectSubfolder

Алгогитм: если в InputFolder есть fits, то считаем, что PutInObjectSubfolder. Если нет файлов, то PutInRootSubfolder

              
Важные замечания:
	(1) Можно настроить, чтобы имя обсерватории было не обязательно
	(2) Ветвление под разные биннинги/гейны/режимы считывания/... Необязательный уровень, в этом случае подбор калибровочных под эти параметры вестисть не будет.
		Данный уровень в иерархии проверяется если:
		а) Указано искать мастера под текущий бининг:
		 - если параметр Config.UseBiningFolder = true
		 - если камера внесена в массив Config.I_USE_BINNING_FOR_THESE_CAMERAS
		б) Указано использовать разные мастера под разные режимы: для этого камера должна быть внесена в массив CAMERA_PRESETS. 
	(3) В папке darks хранятяся и bias, и dark
	(4) Папки уровня DATE можно не использовать, тогда калибровочные будут использованы для любой даты
		Если папка DATE существует, то калибровочные файлы будут использоваться для даты от этой и позже
		Дата может быть в формате 20220101 или 2022-01-01 (разделитель любой), но во вотором случае дата будет собираться из всех цифр в названии (например, 2022-01-01 to 05-01 приведет к дате вида: 202201010501)
	Общие замечания:
	Папки и файлы подбираются на основании их имен папок/файлов, определяемых шаблонами ниже в конфигурации. Содержимое файлов не проверяется! Расширение файлов не проверяется
	Если будет найдено несколько папок/файлов подходящих под шаблон, будет использован первый найденый. Нужно следить, чтобы папки/файлы были уникальными в части ключевых эелментов, определяемых шаблонами.

# ******************************************************************************************************
# 	5. RegistrationReferencesPath
# ******************************************************************************************************
Каталог референсов для StarAlignment задаётся Config.RegistrationReferencesPath.
Поиск использует имя объекта из FITS-ключа OBJECT. Имя файла должно начинаться
точно с имени объекта, за которым следует подчёркивание:

```text
<OBJECT>_<описание>.xisf
NGC 2070_reference.xisf
NGC 2070_20261020_LN.xisf
```

Фактический шаблон: `^<OBJECT>_.*`, без учёта регистра. Пробелы в имени объекта
сохраняются: для OBJECT=NGC 2070 префикс должен быть `NGC 2070_`.
`Light_NGC 2070_...`, `NGC2070_...` и `NGC 2070-...` не подходят.
Фильтр, экспозиция, камера и binning в поиске StarAlignment не проверяются;
референс выбирается по объекту и используется также для регистрации отдельных R/G/B.
Поиск выполняется непосредственно в указанном каталоге, без вложенных папок.
Оставляйте один подходящий референс на объект: при нескольких совпадениях код
берёт последнее найденное, без выбора по качеству или дате.

# * *****************************************************************************************************
# 	6. NormalizationReferencesPath
# ******************************************************************************************************
Каталог референсов для LocalNormalization задаётся Config.NormalizationReferencesPath.
Имя должно начинаться с точного имени объекта из OBJECT и подчёркивания,
а заканчиваться точным обозначением фильтра перед расширением:

```text
<OBJECT>_<описание>_<FILTER>.xisf
NGC 2070_reference_R.xisf
NGC 2070_reference_G.xisf
NGC 2070_reference_B.xisf
NGC 2070_reference_RGB.xisf
```

Часть описания необязательна: `NGC 2070_R.xisf` также подходит.
После фильтра разрешены только служебные суффиксы экспозиции и/или `_LN`:

```text
NGC 2070_reference_R_LN.xisf
NGC 2070_reference_R_20s.xisf
NGC 2070_reference_R_20s_LN.xisf
```

Поиск не учитывает регистр. Допустимые расширения: `.xisf`, `.fits`, `.fit`.
Имя объекта и фильтр воспринимаются буквально, включая пробелы, скобки и другие
специальные символы. Префикс `Light_` перед объектом не допускается.

Фильтр проверяется в конце имени, а не по вхождению где-либо внутри.
Для запроса R файл `NGC 2070_..._d_RGB_c_r_G.xisf` не подходит: его конечный
фильтр — G. RGB также не совпадает с R. Поэтому референсы R/G/B/RGB можно
хранить в одном каталоге. Если нужного канала нет, поиск возвращает «не найдено»,
LocalNormalization для него не запускается, а окно прогресса показывает ошибку.
Подстановка референса другого канала запрещена.

При Config.StrictNormalization=false экспозиция необязательна и не сравнивается
с текущим кадром. При Config.StrictNormalization=true после фильтра требуется
точная экспозиция текущего кадра с суффиксом `s`:

```text
<OBJECT>_<описание>_<FILTER>_<EXPTIME>s.xisf
NGC 2070_reference_R_20s.xisf
NGC 2070_reference_RGB_20s.xisf
```

После экспозиции допустим `_LN`. Камера и binning не проверяются.
Поиск выполняется непосредственно в указанном каталоге. При нескольких точных
совпадениях используется последнее найденное; рекомендуется один подходящий
файл на объект/фильтр и, для строгого режима, экспозицию.

## Workflow: MONO и OSC

В блоке Workflow над Processing выберите кнопку MONO или OSC. Третья кнопка,
OSC CFA Drizzle, пока заблокирована. Настройки Debayer и Split channels находятся
в Processing после Cosmetic Correction и всегда видны: в MONO строка заблокирована. Debayer (VNG)
в OSC включён по умолчанию, его можно отключить. Workflow и настройка Debayer
сохраняются независимо в Settings и экземплярах процесса. Выбор Workflow и
настройки OSC записываются сразу при изменении и восстанавливаются даже после
закрытия через Cancel без сохранения остальных параметров. Split channels работает независимо от Debayer: готовый RGB можно разделять
без повторного VNG. При включённом Split монохромный/CFA-вход без преобразования
в RGB отклоняется с диагностикой до последующих этапов. MONO сохраняет прежний монохромный
конвейер. В OSC после CosmeticCorrection выполняется Debayer VNG; становятся
доступны Split channels и выбор порядка разделения:

- Before StarAlignment: Debayer → R/G/B → ABE → StarAlignment каждого канала → LN каждого канала.
- After StarAlignment: Debayer RGB → ABE RGB → StarAlignment RGB → R/G/B → LN каждого канала.
- Split channels выключен: Debayer RGB → ABE RGB → StarAlignment RGB → LN RGB.

ABE, Register и LN остаются опциональными этапами. Если Register выключен,
After StarAlignment разделяет изображение после предыдущего включённого этапа;
LN по прежней логике требует уже зарегистрированный вход с суффиксом _r.
Integration и CFA Drizzle пока не реализованы.

Опция Retry with mode 2 if registration fails находится под Register и доступна
при включённой регистрации. Config.RegistrationRetryMode2 задаёт её значение
(по умолчанию true); оно сохраняется в Settings и экземплярах процесса. При false
выполняется только режим 1, без повторной попытки.

StarAlignment для каждого кадра сначала использует режим 1: sensitivity=0.50,
distortionCorrection=true. Если executeGlobal завершился неудачей, выбросил
исключение либо outputData/выходной файл не подтверждают результат, этот кадр
повторяется в режиме 2: sensitivity=0.75, distortionCorrection=false. Остальные
параметры одинаковы и соответствуют согласованным профилям. Референс и имя
выходного файла сохраняются. Успешные кадры/каналы повторно не запускаются;
при отмене, отсутствии референса или запрете перезаписи повтор не выполняется.
В лог выводится номер попытки и режим, который завершился успешно. Ошибка этапа
фиксируется после неудачи обоих режимов; только подтверждённый результат
добавляется в FILEARRAY и передаётся в последующие этапы.


Workflow, Split channels и порядок разделения сохраняются в настройках и экземплярах
процесса. Старые настройки NeedDebayer=true автоматически становятся OSC с разделением
до регистрации; false становится MONO. При переключении на MONO предпочтения OSC
сохраняются. В конфигурационном файле Workflow принимает "MONO", "OSC", "OSC_CFA_DRIZZLE" или null
(совместимость со старым NeedDebayer). Зарезервированный OSC_CFA_DRIZZLE проходит
сохранение/загрузку Settings и экземпляров процесса без замены на MONO, но Execute
и engine блокируют его запуск до реализации pipeline.

NeedDebayer — единственная настройка Debayer: она не сбрасывается при выборе MONO,
а engine проверяет одновременно Workflow и NeedDebayer. Прежний OSCDebayer читается
только при миграции старых Settings/экземпляров; новые данные используют версию
схемы WorkflowSettingsVersion=2 и не записывают OSCDebayer. Монохромные файлы без CFA-признаков и уже
цветные изображения проходят этап Debayer без преобразования.

Bayer-паттерн определяется по CFA:SourcePattern, BAYERPAT или прежнему значению
FILTER (RGGB, BGGR, GBRG, GRBG). VNG выполняется файловым Debayer: targetItems
с одним входом и executeGlobal(). Параметр паттерна — cfaPattern, выход — RGB XISF.
Процесс сам загружает и сохраняет изображение; getFileHeaderData по-прежнему
открывает вход для чтения заголовка. Фактический результат берётся из outputFileData,
проверяется и перемещается из отдельного временного каталога к принятому имени.
При ошибке временный каталог сохраняется для диагностики, его путь выводится в консоль.
Результаты сохраняются в DebayerdFolderName
как RGB XISF: например light_d_RGB_c_cc.xisf. Split является отдельным этапом: до
регистрации он сохраняет light_d_RGB_p_R_c_cc.xisf и аналогично G/B в SplitFolderName.
Для готового RGB без Debayer имя будет light_p_R_c.xisf. Метаданные RGB-файла
сохраняет сам Debayer; фильтр исходной съёмки может остаться прежним. Для LN
цветной вход распознаётся как RGB по типу изображения. При Split сохраняются
точность отсчётов и метаданные съёмки, CFA-метаданные удаляются, FILTER получает
значение R/G/B. Для LocalNormalization нужны соответствующие
опорные изображения с этими фильтрами.

При разделении после регистрации результаты сохраняются в SplitFolderName (по
умолчанию split): light_d_RGB_s_R_c_cc_r.xisf и аналогично G/B. Маркер _s_ отличает
их от каналов, выделенных до регистрации, и предотвращает смешивание результатов
двух порядков обработки. Для LN RGB нужен референс с FILTER=RGB; для R/G/B —
референсы соответствующих каналов.

Учёт использует общую FILEARRAY: debayered связывает исходник с RGB, splitBefore —
RGB с каналами до регистрации, split — RGB с каналами после регистрации. Каждый
результат имеет собственную запись. Маркеры _p_ и _s_ различают два порядка;
ScanArray пропускает продукты другого порядка при смене настроек.
Второй проход ScanArray восстанавливает недостающие этапы этих записей,
не повторяя регистрацию для уже выделенных после неё каналов.
Завершённый Debayer не повторяется при ошибке следующего этапа; при новом запуске
SkipExistingFiles позволяет использовать сохранённые каналы и создать недостающий.
SubframeSelector запускается после обоих проходов. В очередь копирования финальных
файлов попадают только результаты завершённого выбранного конвейера, включая
повторный проход и режим с выключенным SubframeSelector.

Проверки без PixInsight: node AutoCalibrate/tests/debayer.test.js.
Это проверки управления процессами с имитацией API. В PixInsight нужно проверить
на небольшой серии CFA: VNG против ручного запуска, RGB и R/G/B, метаданные,
оба порядка Split/StarAlignment, повторный запуск с одним удалённым каналом
и продолжение после ошибки следующего этапа.

LocalNormalization: под строкой этапа доступен Scale evaluation с вариантами
PSF Signal и Multiscale Analysis. Config.NormalizationUsePSF=true
выбирает PSF Signal (значение по умолчанию), false — Multiscale Analysis. Выбор
сохраняется в Settings и экземплярах процесса и передаётся в scaleEvaluationMethod.
Scale и No scale component задаются отдельно. При включённом No scale component
множитель нормализации равен 1; для применения оценки масштаба эту галочку нужно снять.

При ошибке LocalNormalization в списке ошибок окна прогресса отображаются имя
входного файла и причина: отсутствующий референс, нечитаемый заголовок,
незарегистрированный вход, ошибка процесса или неподтверждённый/невалидный
результат outputData. Ошибка возвращает false, а не исходные файлы: неудачный
вход не считается успешно нормализованным и не передаётся дальше в этом проходе.
Новый неподтверждённый выход удаляется, чтобы второй проход мог повторить этап.
Пользовательская отмена не добавляется в список ошибок.

## Integration

Enable Integration запускает ImageIntegration после обоих проходов Processing. Используется общий список конечных файлов approveFileList: он собирается, когда включён SubframeSelector или Integration. Измерения и выражения SubframeSelector не используются для отбора или взвешивания интегрируемых кадров.

Входы должны быть выровнены на общий референс и иметь суффикс _r или _r_n. Группы формируются по OBJECT и FILTER; RGB-изображения образуют отдельную группу RGB. Отсутствующие файлы, OBJECT/FILTER, CFA и несовместимая геометрия выводятся в список ошибок. Кадры с разными размерами внутри одной группы не складываются. Для группировки используется общий getFileHeaderData(): отдельного readInput нет. Уже прочитанные при Processing/SFS метаданные переиспользуются из кэша текущего запуска; неизвестный готовый файл читается общим методом один раз. Проверки группировки не требуют калибровочных заголовков (например CCD-TEMP), а обычные этапы сохраняют прежние обязательные проверки. Возвращается независимая копия метаданных, отсутствующие поля не наследуются от предыдущего файла; окна чтения всегда закрываются.

Сложение: Average, нормализация Additive with scaling и нормализация rejection Scale + zero offset. Если для всех кадров группы есть XNML, вместо нормализованных изображений передаются соответствующие выровненные (_r) файлы с путями XNML в четвёртом столбце images. Включаются LocalNormalization и LocalRejectionNormalization. Если XNML нет ни у одного кадра, остаются текущие входы и глобальная нормализация; ветка для готовых _r_n изображений сохранена. При сбое LN зарегистрированные кадры сохраняются отдельно для Integration; ошибка LN остаётся в консоли и статусе файла. При неполном наборе XNML группа складывается с глобальной нормализацией без XNML: используются зарегистрированные исходники, где они доступны, иначе готовые нормализованные изображения. Если нормализованный файл отсутствует, Integration использует его зарегистрированный источник. Во всех случаях fallback выводится предупреждение; кадры без доступного изображения по-прежнему считаются ошибкой. Повторно успешно нормализованный кадр заменяет свой fallback, без двойного включения в сумму. Drizzle пока не используется.

Автоматический rejection:
- менее 3 кадров — сообщение об ошибке, группа пропускается;
- 3–5 кадров — Percentile clipping, пороги 0.20 / 0.10;
- от 6 кадров — Winsorized Sigma clipping с IntegrationSigmaLow / IntegrationSigmaHigh.

Поля Sigma low и Sigma high находятся в одной строке. Начальные пороги 4.00 / 3.00, диапазон 0–10. Они применяются только к Winsorized Sigma; в лог выводится фактически выбранный метод. В UI добавлен выбор Weights: PSF Signal Weight (по умолчанию), Noise evaluation (native SNREstimate) или FITS Keyword. Имя FITS keyword задаётся только в AutoCalibrate-config-default.js через Config.IntegrationWeightKeyword (по умолчанию SSWEIGHT). Поля имени keyword в UI нет, из Settings и параметров экземпляра оно не читается и туда не сохраняется. Этот числовой keyword должен уже существовать во входных кадрах: AutoCalibrate его не создаёт и не подставляет другой режим при его отсутствии. Взвешивание не применяет порог отбора кадров (minWeight = 0). В конфиге и сериализации сохраняются NeedIntegration, IntegrationWeightMode, IntegrationSigmaLow и IntegrationSigmaHigh. Дробные значения сохраняются в Settings и экземпляре процесса.

Результат сохраняется в <база>/Integrated/: <объект>_<фильтр>_master.xisf, _rejection_low.xisf и _rejection_high.xisf. Для ABSOLUTE база — OutputPath; для режимов PUT_IN_ROOT_SUBFOLDER, PUT_IN_OBJECT_SUBFOLDER и PUT_FINALS_IN_OBJECT_SUBFOLDER — InputPath/OutputPath; для относительных режимов — InputPath (общая папка мастеров для всего запуска). Недопустимые символы заменяются в именах файлов; коллизии имён приводят к ошибке. Каталог Integrated исключается из повторного сканирования.

Integration всегда выполняет новое сложение: SkipExistingFiles и OverwriteAllFiles не влияют на сохранение сумм. Если хотя бы один из трёх выходных файлов уже существует, для всего набора выбирается первый свободный индекс: _master_1.xisf, _rejection_low_1.xisf, _rejection_high_1.xisf, затем _2 и далее. Все прежние файлы сохраняются. Изображения сохраняются напрямую в Integrated через saveAs: сначала карты rejection, затем мастер. Временные каталоги, переносы и резервные копии не используются. Окна, созданные ImageIntegration, закрываются после сохранения или ошибки. После обработки всех групп сохранённые мастера открываются в PixInsight с конечных путей, только для нового сложения. Карты rejection остаются закрытыми.

Ошибка одной группы не останавливает остальные; отмена останавливает этап. В основном окне прогресса показывается одна краткая запись о неудаче для каждого объекта/канала; подробности по файлам остаются в консоли. Ошибки подготовки файлов без определённой группы суммируются отдельно. CFA Drizzle не реализован.

## Отмена обработки

Все этапы engine используют общий метод isCancelled(). Он проверяет console.abortRequested, флаг окна прогресса и engine.abortRequested. Обнаруженная отмена сохраняется в engine до конца его текущего экземпляра, даже если внешний флаг сброшен. Проверки выполняются перед этапами, между файлами/каналами и после native-процессов. Отмена не добавляет сообщение об ошибке файла или группы и не запускает следующий этап. Уже созданные результаты сохраняются; открытые рабочие окна закрываются в предусмотренных для этапа cleanup/finally.

## Статусы неудачной обработки

Общий метод engine.reportFailure(target, message) выводит краткий статус в окно прогресса. target — путь входного файла для обычных этапов или объект/канал для Integration. Существующие сообщения этапов сохранены; подробная техническая диагностика остаётся в консоли у вызывающего кода. При отмене статус ошибки не добавляется. Метод не меняет результат этапа и не добавляет повторные сообщения: для Integration он вызывается один раз на неудачную группу.

## Drizzle Integration: интерфейс

В блоке Integration строки расположены так: Enable Integration, Weights, Sigma low / Sigma high, Drizzle Integration, Drizzle scale / Drop shrink. Drizzle Integration — отдельный флажок: он включает Enable Integration и блокирует его отключение до снятия Drizzle. При снятии Drizzle обычный Integration остаётся включённым, его снова можно отключить. Выбор Drizzle доступен для MONO, OSC без разделения каналов и OSC с включённым Split channels перед StarAlignment, даже когда обычный Integration выключен. При других workflow флажок Drizzle неактивен; сохранённое предпочтение не сбрасывается. Drizzle scale и Drop shrink размещены в одной строке, всегда видимы и активны только при выбранном доступном Drizzle и включённом Integration. Начальные значения: scale 2 (выпадающий список 1, 2, 3), drop shrink 0.90 (диапазон 0.10–1.00). Метод и оба параметра сохраняются в config-default, Settings и параметрах экземпляра. StarAlignment создаёт XDRZ при включённом Drizzle. Если у всей группы XDRZ отсутствуют, Integration повторяет регистрацию найденных в FILEARRAY исходников до StarAlignment относительно текущего референса, включая генерацию XDRZ; существующие XNML сохраняются. Если набор XDRZ неполный или восстановление невозможно, сохраняется обычная сумма с предупреждением. ImageIntegration подготавливает rejection/weights в XDRZ; при полном наборе XNML оба процесса используют локальную нормализацию. Обычная сумма сохраняется обязательно. Затем DrizzleIntegration сохраняет отдельный _drizzle_master и _drizzle_weights с первым свободным общим индексом. При успехе открывается drizzle-мастер, при сбое — обычный. CFA Drizzle и split после регистрации не поддерживаются.

## Данные LocalNormalization (XNML)

Опция Generate XNML в Processing сохраняется как NormalizationGenerateData (по умолчанию false) в конфиге, Settings и экземпляре процесса. Она доступна при включённом LocalNormalization и размещена в строке Scale / No scale component.

При включении LocalNormalization сохраняет данные функций вместе с нормализованными изображениями. XNML берётся из outputData процесса и переносится в <папка нормализации>/xnml/<имя выровненного кадра>.xnml. Уже существующие нормализованные изображения не пропускаются, если запрошенного XNML ещё нет: в этом случае выполняется только генерация данных, без перезаписи изображения. Второй проход также восстанавливает недостающие XNML, если доступен зарегистрированный источник.

Integration автоматически использует полные наборы XNML независимо от состояния флажка генерации. Данные применяются к зарегистрированным исходникам; применять те же функции к уже нормализованным пикселям повторно не требуется. Для split после StarAlignment используются зарегистрированные поканальные файлы из папки split, а не родительский RGB-кадр. Для готовых результатов связь определяется по FILEARRAY или по имени файла в соседних registered/split папках.
